MILESTONE 5 SUMMARY
===================

Status: In progress. Started November 5, 2026.

Objective
---------
Turn map.html into a phone app. It does the same job, but runs on an Android
phone and an iPhone and reads its data from Firebase instead of local files.

Done when: the app runs on the owner's Android phone and iPhone through Expo
Go and does what map.html does, with data from Firebase.

Words Used Here
---------------
- Expo: a toolkit for building phone apps in JavaScript/TypeScript. One
  codebase serves both Android and iPhone.
- React Native: what Expo is built on. It turns our code into real phone
  screens and buttons, rather than a web page.
- Expo Go: a phone app that runs our project while we build it, so we don't
  need to make a full app build for every change.
- SDK: the bundle of Expo tools for one release. We are on SDK 58. The
  project and Expo Go must be on the same SDK.
- Dev server: a program on the laptop (started by "npx expo start") that
  sends our code to the phone. The QR code tells the phone where to find it.
- Emulator: a pretend Android phone in a window on the laptop.
- Node.js: runs JavaScript on the laptop, outside a browser. Expo's tools
  are written in JavaScript, so they need it.
- npm / npx: npm installs JavaScript packages. npx runs a tool from a package.
- Package: code someone else wrote that we reuse. Installed packages go in
  app/node_modules.

Steps Taken So Far, and Why
---------------------------

1. Checked what was already on the laptop
   Why: to install only what was missing. Node.js and Android Studio were
   not there; Git and winget (Windows' installer) were.

2. Installed Node.js LTS with winget
   Why: Expo's tools need it. LTS is the long-term support version, meant
   to be stable.

3. Created the project with "npx create-expo-app@latest app"
   Why: it generates a working starter app, so we begin from something that
   runs. It lives in its own app/ folder, separate from the Python pipeline.
   "@latest" gives the newest SDK, here 58.

4. Installed the packages with "npm install"
   Why: the starter app lists the packages it needs in package.json, and
   this downloads them (572 packages). node_modules is not put on GitHub
   because it is large and can be rebuilt from package.json and
   package-lock.json.

5. Ran the health check with "npx expo-doctor"
   Why: it finds version conflicts and setup problems early. 20 of 20 checks
   passed.

6. Test-compiled for both platforms with "npx expo export"
   Why: to prove the code builds for Android and iPhone before bringing a
   phone into it. Both succeeded, so a later problem on a phone is more
   likely the connection than the code.

7. Started installing Android Studio
   Why: it provides the Android emulator, for testing without picking up a
   phone. Not needed for the iPhone. The first attempt failed when the
   network dropped, so it was started again.

8. Read Expo's current docs for maps and Expo Go
   Why: Expo changes with each SDK, and the plan relied on assumptions about
   Expo Go. This found the iPhone question under Open Issues.

9. Committed the app/ folder to GitHub
   Why: so the work is saved and its history can be reviewed.

10. Connected the iPhone (November 7): the welcome screen opened in Expo Go
   - Installed Expo Go from the App Store (free; developer shown as
     "Nametag", seller 650 Industries) and signed in as vix-bram
     Why: on a real iPhone, Expo Go only opens a project when the phone and
     the laptop are signed in to the same Expo account
   - Logged the laptop in with "npx expo login --no-browser" (asks for the
     username and password in the terminal)
     Why: plain "npx expo login" crashes on Windows. It opens the browser
     with an old Windows command that treats each "&" in the login link as
     a new command, so the link is cut short and Expo never hears back
   - On Starbucks Wi-Fi the phone couldn't reach the laptop ("server could
     not be found"); on another network it worked
     Why: public Wi-Fi often blocks devices from reaching each other
     (client isolation). "npx expo start --tunnel" gets around it
   - The terminal didn't know "npx" until VS Code was restarted
     Why: programs keep the PATH they started with, and VS Code was open
     before Node.js was installed

11. First map on the iPhone (November 7): campus map with three test pins
   - Cleared out the template with "npm run reset-project" (chose to delete
     the sample screens rather than keep a copy; they are in git history)
     Why: start from one empty screen instead of Expo's demo
   - Installed the map with "npx expo install react-native-maps"
     Why: "expo install" picks the version that matches SDK 58 (1.29.11);
     Expo Go already contains it, so no extra setup or key was needed.
     On the iPhone it shows Apple Maps
   - Named the app "GT Event Map" (app.json) and gave it a navy header
   - Map opens on the same center as map.html, with gold/navy numbered pins
     at Clough, the Student Center and Klaus. Tapping one shows its name
     Why test pins first: if something is wrong, we know it's the map and
     not the data. Real events from Firebase come next
   - Checked with "npx tsc --noEmit" (TypeScript finds type mistakes),
     "npx expo-doctor" and a test compile before looking on the phone
   - npm reports 5 moderate warnings in Expo's own laptop tools (glob,
     minimatch); left alone, since nothing in them ships to phones and the
     suggested "--force" fix would install incompatible versions
   Checked by the owner on the iPhone. The gear button at the top right is
   Expo Go's developer menu, not part of the app

12. Real events, filters, the list and an offline copy (November 11)
   - Events come from https://gt-event-map.web.app/events.json, pinned by
     building with the lat/lng locate.py wrote onto each event. Tapping a
     pin opens a panel with the building's events (name opens GT's page)
     Why not gt_buildings.json: the pins only need each event's own
     coordinates. The app doesn't download the building list; the daily
     job still publishes it (small, may be useful later, e.g. a building
     search)
   - Time frame chips: Today / Tomorrow / Next 7 days / Pick a date (the
     phone's own calendar: a pop-up on Android, a small date button on the
     iPhone). Days are always Atlanta's, whatever time zone the phone is in
   - "All categories" button opens the 10 checkboxes (Food + GT's names,
     as in map.html) with counts and All / None
   - "Not on the map (N)" button opens the list, in map.html's sections
     (Online, Off campus, Location not matched/found, No location listed),
     with the same time frame and categories as the pins
   - Offline: each good download is saved on the phone (expo-file-system).
     If the download fails or takes over 15 seconds, the saved copy shows,
     with "Couldn't update. Showing the events saved <time>. Try again"
     Why: students open the app in basements and on bad Wi-Fi; an old list
     is better than none. A broken file is never shown or saved
   - When the app comes back from the background after over an hour, it
     downloads the events again; ended events drop off every 5 minutes
   - Packages added with "npx expo install": expo-file-system and
     @react-native-community/datetimepicker (both already inside Expo Go).
     "npx expo install --fix" updated 10 Expo packages to newer patch
     versions, as expo-doctor asked. "npx expo lint" set up ESLint
     (eslint.config.js)
   - Checked: tsc, eslint, expo-doctor (20/20), a test compile for both
     platforms, and a Node test of the rules on the live events.json (on
     Nov 11, Next 7 days: 53 events = 29 pinned + 24 in the list; the days
     when daylight saving starts and ends get the right midnight)
   Checked by the owner on the iPhone (November 11)

Key Files
---------
- app/package.json: the packages the app uses, and the Expo version
- app/app.json: the app's settings (name, icons, ...)
- app/src/app/: the app's screens. Each file here is a screen
  (index.tsx is the map; _layout.tsx is the header around it)
- app/src/components/building-pin.tsx: the gold numbered pin
- app/src/components/filter-bar.tsx: time frame chips and date picker
- app/src/components/category-picker.tsx: the category checkboxes
- app/src/components/bottom-panel.tsx: the panel for a building's events
  and for the "Not on the map" list
- app/src/components/event-card.tsx: one event (name, time, place, tags)
- app/src/lib/events.ts: the rules (time frames, categories, pins, list);
  imports nothing, so it can be tested with plain Node
- app/src/lib/saved-events.ts: download, and the copy saved on the phone
- app/src/constants/campus.ts: GT colors and the map's starting area
- app/AGENTS.md: Expo's notes for AI coding assistants
